# ForteBank: локальный API и проверяемые доказательства

Эта инструкция описывает отдельный технический каркас `src.forte.api` без анализатора.
Работающий запуск с Qwen находится в `src.forte.service` и описан в
[инструкции сервиса](forte_service.md). Без анализатора каркас возвращает
`failed/model_unavailable`. Синтетические адаптеры существуют
только в тестах. Ни формат ответа, ни корректные JPEG сами по себе не доказывают
правильность распознавания или готовность к сдаче.

Код написан для этого проекта; файлы стороннего готового решения не копировались.
Старые табличные модули, конфигурации и учебные результаты сохранены.
Фактические команды, результаты тестов и ограничения: [отчёт проверки](../reports/forte_api_check.md).

## Запуск на ноутбуке

Из корня репозитория создайте **новое** окружение. Если указанный каталог уже существует,
выберите другой путь; старую среду не пересоздавайте.

```powershell
py -3.12 -m venv outputs/forte-api-env/.venv
$python = (Resolve-Path outputs/forte-api-env/.venv/Scripts/python.exe).Path
& $python -m pip install -r requirements-forte.txt
$env:FORTE_API_KEY = & $python -c "import secrets; print(secrets.token_urlsafe(32))"
& $python -m src.forte.api
```

Ключ хранится в переменной среды текущего процесса. Не вставляйте его в код, Git,
скриншоты или публичные логи. Сервер слушает `127.0.0.1:8000`; запускайте один процесс
Uvicorn, поскольку очередь и результаты находятся в памяти этого процесса.
В Linux команды аналогичны с `.venv/bin/python` и переменными среды оболочки.

Для тестов добавьте `requirements-dev.txt` и `requirements-catboost.txt` в эту же
новую среду. Тесты создают только явно обозначенные синтетические MOV/JPEG/таблицы:

```powershell
& $python -m pip install -r requirements-dev.txt -r requirements-catboost.txt
& $python -m pytest -q
& $python -m ruff check .
& $python -m ruff format --check .
& $python -m pip check
& $python -m compileall -q src tests experiments
```

Без optional ForteBank-зависимостей его тестовые модули пропускаются. В CI добавлена
явная установка `requirements-forte.txt`, чтобы эти проверки выполнялись в обеих
существующих jobs. Успешный запуск на GitHub нужно подтвердить после публикации;
локальный запуск Windows не подтверждает Ubuntu или GitHub Actions.

## HTTP-контракт

У обоих маршрутов обязателен заголовок `X-API-Key`.

- `POST /api/v1/analyze`: `multipart/form-data`, ровно одно поле `file`, имя с `.mov`.
  Принятый запрос возвращает HTTP 202 и `{"job_id": "..."}`.
- `GET /api/v1/jobs/{job_id}`: `processing`, `done` или `failed`.
  Для `done` присутствуют `verdict` и `violations`, для `failed` — безопасный код ошибки.
- Неверный ключ: 401; неизвестная или чужая задача: 404; заполненная очередь: 429;
  превышение размера: 413; истечение времени при загрузке: 408.

Для нескольких операторов передайте `create_app(api_keys={principal: secret, ...})`
с разными ключами. Один и тот же ключ означает одного оператора. Общих cookies,
списка задач и маршрута выдачи загруженных видео нет.

При `violation` список событий непустой; при `no_violation` он пуст.
Каждое событие содержит:

```text
type: непустая строка
timecode_sec: конечное число внутри видео
description: непустая строка
evidence_frames: 1–3 объекта {timestamp_sec, image_base64}
```

`image_base64` должен декодироваться именно в JPEG. Сервер создаёт кадры из принятого
видео самостоятельно, сверяет содержимое и временные метки. Изображения от модели
не принимаются как доказательства. Текущая реализация выдаёт один JPEG на событие.

Временная ось начинается с первого декодированного PTS. Финальный `timecode_sec`
выравнивается по PTS выбранного кадра. Максимальное расстояние до запрошенного
момента — внутренний предел извлечения 1 секунда, **не официальная метрика**.
Распознавание события и правовая обоснованность проверяются отдельно человеком.

## Анализатор и ограничения исполнения

Оператор может задать `FORTE_ANALYZER=trusted_module:function`. Доверенная функция
получает только нейтральный путь `input.mov` и абсолютный `deadline` из
`time.monotonic()`. Имена исходников, аннотации и метки в неё не передаются.

```text
analyze(video_path, *, deadline) -> {
  verdict: violation | no_violation,
  violations: [{type, timecode_sec, description}, ...],
  analysis_complete: true,
  uncertain: false
}
```

Это контракт, а не пример фактического результата модели. Адаптер обязан отвергать
обрезание ответа, отказ, неполный анализ и неопределённость. Их нельзя превращать
в `no_violation`. Хеш принятой копии проверяется до/после анализа и извлечения кадров.

По умолчанию принимаются не более двух одновременно активных задач, включая
загрузку, очередь и исполнение. Размер файла ограничен 128 MiB. Общий срок 300 секунд
начинается при входе в обработчик POST, включает загрузку и очередь. Один worker
запускает адаптер в отдельном процессе и останавливает его при истечении срока.
Внешний reverse proxy при размещении должен также ограничивать медленную передачу
заголовков и размер запроса до попадания в приложение.

Процесс — не sandbox недоверенного кода. Адаптер не должен создавать отделённые
процессы модели, загружать данные наружу или читать сторонние локальные источники.
Оригиналы открываются только для чтения. Рабочая копия находится в
`outputs/forte-api/uploads/job-*/input.mov` и очищается после обработки.
Результаты временные: теряются после перезапуска, срок хранения до часа,
не более 100 завершённых задач и 64 MiB суммарных JSON-результатов; старейшие удаляются
при превышении лимитов. Для жюри нужен отдельный
проверенный план сохранения нужных артефактов; текущий API их не публикует.

## Оценка качества

`src.forte.evaluation.evaluate_manifest` использует существующие записи `videos`
с полями `key`, `file`, `source_sha256`, `split` и `annotations[{class}]`.
`base_dir` задаёт корень локальных файлов. Метки должны быть 0/1 и согласованы у aliases.
Разбиение не создаётся заново. По умолчанию используется `development`;
`holdout` требует явного разрешения и не используется для выбора параметров.

Проверяются пересечения между частями по исходным SHA, фактическим хешам локальных
файлов и переданным `related_group`. Если группы связанных сцен не предоставлены
для всех записей, отчёт честно указывает `NOT VERIFIED`. Автоматически угадывать
смысловую связь сцен evaluator не умеет. Различаются SHA исходного MOV и его remux-копии.

Анализатор получает временный файл `video.mov` и deadline, без разметки. Итоговые
TP/TN/FP/FN и метрики относятся только к полным проверенным результатам; отдельно
сохраняются ошибки, неполнота, таймауты, количество попыток и coverage. Их нельзя
скрывать при сравнении моделей. Время включает копирование, анализ, доказательства
и проверку целостности. У offline callable дедлайн кооперативный: зависшую функцию
он не прерывает; для HTTP действует отдельный принудительно завершаемый worker.

Для каждого запуска нужен новый каталог и `run_metadata` с `analyzer_version`,
`code_revision` и `settings`. Сохраняются снимок manifest, версии, SHA, настройки,
числовой summary и приватный `outcomes.jsonl`, который может содержать описания и JPEG.
Его нельзя отправлять в облачный чат или коммитить. Метрики реальных видео для этого
нового API ещё не получены; синтетические тесты не являются конкурсным экспериментом.

## Возможное размещение на GPU: только план

Пользователь сообщил о $50 кредитов NVIDIA и предоставил ссылку Brev. Тип кредита
пока UNKNOWN: API-кредиты NVIDIA нельзя считать кредитами на аренду VM в Brev.
Инстанс, фактический баланс, применимость ваучера, цена и публичный адрес не подтверждены.
Ресурсы не создавались, данные наружу не загружались.
Размещение конкурсных видео у провайдера требует разрешения организаторов и пользователя.

После такого разрешения возможна схема: HTTPS 443 → reverse proxy → API на loopback →
локальный GPU worker. Не открывайте наружу модель, Jupyter и произвольные каталоги.
Для HTTPS с Caddy нужны корректные DNS-записи и доступные входящие порты;
инструкция зависит от выбранной VM. [Caddy HTTPS](https://caddyserver.com/docs/quick-starts/https)

Brev Secure Link использует авторизацию Brev; tunnel URL может требовать входа
через браузер. Такой адрес нельзя заранее считать совместимым с автоматическим
жюри, отправляющим только `X-API-Key`. SSH port-forward даёт локальный доступ.
[Brev Network](https://docs.nvidia.com/brev/concepts/launchables),
[Brev tunnels](https://docs.nvidia.com/brev/guides/console-reference),
[Brev connectivity](https://docs.nvidia.com/brev/cli/connectivity)

Проверка внешнего клиента должна подтвердить JSON без login redirect/cookie,
POST 202, последующий done/failed, 401 для неверного ключа, срок с очередью,
декодируемые доказательства и работу модели без исходящих сетевых запросов.
До выполнения этих проверок публичная готовность — NOT VERIFIED.

Stop прекращает оплату вычислений, но хранение может оставаться платным; Delete
удаляет данные. Сохраняемый путь workspace и доступность GPU после возобновления
нужно проверить по условиям инстанса. [Brev lifecycle](https://docs.nvidia.com/brev/concepts/gpu-instances)
Бюджет считайте по фактической цене: `(доступные кредиты − резерв) / цена в час`,
отдельно учитывая хранение. Не предполагается бесплатное бессрочное хранение.
