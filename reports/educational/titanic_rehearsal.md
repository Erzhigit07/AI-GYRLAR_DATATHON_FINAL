## Подготовленные конфигурации

- `configs/educational/titanic_group.json`: group holdout по Ticket, seed 42,
  test_size 0.2 (доля групп, не обязательно ровно 20% строк).
- `configs/educational/titanic_random.json`: random stratified holdout, seed 42,
  test_size 0.2; альтернативная процедура оценки, не оптимизация seed.

Цель: Survived; идентификатор: PassengerId. Признаки: Pclass, Sex, Age, SibSp,
Parch, Fare, Embarked. Pclass читается как категория. Метрики: accuracy,
precision, recall, F1; positive_label=1, average=binary. Accuracy — основная
метрика учебного соревнования, остальные — диагностические.

Параметры заданы до получения оценок; подбора по holdout не было:
Logistic Regression C=1, max_iter=2000; Random Forest 300 деревьев,
min_samples_leaf=2; CatBoost 300 итераций, depth=5, learning_rate=0.05.
Baseline — наиболее частый класс. Предобработка используется из существующего
Pipeline: медиана/масштабирование чисел, мода/one-hot категорий только на train.

CatBoost 1.2.8 доступен. Все четыре pipeline успешно создаются, но на Titanic
не обучались. Каталоги результатов изолированы под `outputs/educational/titanic/`;
dataset_label явно содержит EDUCATIONAL ONLY. data_kind=real означает происхождение
данных, а не принадлежность к DATATHON.

## Протокол после получения файлов

1. Записать источник и SHA-256 исходных файлов; проверить схему, ID, наличие цели,
   типы, пропуски, дубликаты и согласованность train/test. Не изменять оригиналы.
2. Зафиксировать split до целевого EDA и выбора дополнительных признаков.
   Исследовать обучающую часть через quality_report и plot_eda; поздний анализ
   holdout использовать только как диагностику, без повторной подстройки.
3. Проверить повторяющиеся Ticket и семейные связи, пересечения групп на random
   split. Ticket исключён из признаков; group split разделяет билеты, но не гарантирует
   разделения всех семей с разными билетами. При необходимости сформировать связанные
   группы отдельно, без использования Survived.
4. Проверить утечки: исключены Survived, PassengerId, Name, Ticket, Cabin из features;
   отсутствие этих столбцов не доказывает отсутствие всех утечек. Проверить доступность
   остальных признаков до исхода события. Не использовать test-ответы, внешние списки
   выживших и gender_submission как ground truth.
5. Запустить неизменённый train для каждой конфигурации:

```bash
python -m src.train --config configs/educational/titanic_group.json
python -m src.train --config configs/educational/titanic_random.json
```

6. Внутри каждого split сравнить все модели с baseline. Результаты двух способов
   разбиения показывать отдельно: они оценивают разные условия обобщения.
7. По validation_predictions.csv посчитать confusion matrix, FP/FN и ошибки по
   Sex/Pclass/возрастным группам/пропускам Age, указывать размеры подгрупп. Проверить
   переобучение сравнением train и holdout и ограниченность выводов на малых группах.
8. Проверить сохранённые модели, схему/порядок/ID предсказаний на официальном test;
   его истинные метки неизвестны, поэтому локальные метрики на test не вычислять.
9. Проверить неизменность хешей, сохранить фактический отчёт отдельно от DATATHON.
   Не отправлять датасеты, модели, построчные предсказания или submissions на GitHub/Kaggle.
